# DTKS_BE Security Remediation & Architecture Report

**Scope:** `backend/src/**`, `backend/migrations/**`, `server.ts`, `.gitignore`  
**Stack:** Cloudflare Workers (ES Modules) + Cloudflare D1 (SQLite) + Cloudflare R2 + WebCrypto + Resend

## 1. Master Security Remediation Matrix (Findings & Verification)

| Finding | Severity | Remediation Implemented | Key Verification |
| :--- | :--- | :--- | :--- |
| **Order Tracking Enumeration & PII Exposure (`GET /orders/track?ref=&email=`)** | Critical | Replaced query-parameter lookup with `POST /api/v1/orders/track` (`{ token }`) backed by 256-bit random tokens hashed with SHA-256 (`order_tracking_tokens`, 90d TTL, `revoked_at` / `expires_at` / `last_accessed_at`). Returns non-PII `mapTrackedOrderSummary` (strips email/phone/customer_name/admin_notes) and uniform `404 ORDER_NOT_FOUND`. Legacy `GET /api/v1/orders/track` returns `410 LEGACY_TRACKING_DISABLED`. | `security_remediation.test.js` #1, `backend.test.js` #11, `auth_and_accounts.test.js` `B1` |
| **Guest-to-Client Account Order Injection** | High | Unauthenticated guest `POST /api/v1/orders` now sets `customer_id = NULL` (never attaching guest submissions to existing verified `customer_accounts`). Historical guest orders created *before* client registration (`julianday(orders.created_at) <= julianday(account.created_at)`) link only after email verification. Cookie-carrying `POST /orders` enforces `X-CSRF-Token`. | `security_remediation.test.js` #1 & #3 |
| **Session Tokens Exposed in JSON / Browser Storage** | High | Default `/auth/login`, `/auth/refresh`, `/client/auth/login`, `/client/auth/refresh` issue host-only `HttpOnly; SameSite=Lax; Secure` cookies (`dtks_access`, `dtks_refresh`, `dtks_csrf`; `dtks_client_access`, `dtks_client_refresh`, `dtks_client_csrf`), omit raw tokens from JSON (`authMode: 'cookie'`), provide `GET /auth/csrf` & `GET /client/auth/csrf`, clear cookies on logout/password-change, and require explicit `X-Auth-Mode: bearer` opt-in for non-cookie API clients. Fixed `server.ts` multi-cookie forwarding via `headers.getSetCookie()`. | `security_remediation.test.js` #3 |
| **Refresh Token Replay Detection vs Single-Device Logout** | High | Added `revoke_reason TEXT` (`'rotated'` vs `'logout'`) on `refresh_sessions` & `customer_refresh_sessions`. Reusing a `'rotated'` token triggers full session cascade revocation + `token_version` increment + audit log (`401 REFRESH_TOKEN_REPLAY_DETECTED`), while single-device `'logout'` rejects with `401` without invalidating sibling devices. | `security_remediation.test.js` #3, `backend.test.js` #5, `auth_and_accounts.test.js` `C1` & `C3` |
| **Query-String Token Leakage in Emails** | Medium | Standardized all verification, password reset, admin invitation, and order tracking emails to deliver raw tokens in URL fragments (`#token=...`) instead of `?token=` or `?ref=&email=` query parameters. | `security_remediation.test.js` #1 & #2, `admin_password_reset.test.js` |
| **Client Recovery Enumeration, Delivery Failure Token Loss & Blocking Security Alerts** | High | `resendClientVerification` & `forgotClientPassword` return uniform `200 OK` `{ requested: true }` on delivery failure with targeted revocation of only the failed token (keeping prior valid tokens active); claims use SQL `julianday(expires_at) > julianday(?)`; `changeClientPassword`, `resetClientPassword`, and `deactivateClientAccount` send non-blocking security alerts (`try/catch` + audit log). | `security_remediation.test.js` #2, `auth_and_accounts.test.js` `B2` & `C3` |
| **Fail-Open Rate Limiters & Missing Client Route Layering** | High | Marked all auth, registration, verification, recovery, tracking, and public submission rate limiters `failClosedInProd: true` (`503 RATE_LIMITER_UNAVAILABLE` in production on DB outage); added layered IP + keyed-HMAC buckets for client registration, verification, password reset, and order tracking (`enforceOrderTrackingRateLimits`); lowered `publicSubmission` to `15 / 10m`. | `security_remediation.test.js` #2, `admin_password_reset.test.js` |
| **Production CORS Bypass & Cleartext HTTP Auth** | High | Removed `ALLOW_LOCAL_CORS` bypass when `ENVIRONMENT === 'production'`; enforced HTTPS (`403 HTTPS_REQUIRED`) on `/auth/*`, `/client/*`, `/admin/*`, and `/orders/track` in production. | `security_remediation.test.js` #5, `contract_and_security.test.js` #4 |
| **R2 Unbounded Buffering, Key Traversal & Serving Headers** | High | Added pre-read `Content-Length`, `file.size`, `rawText.length`, and base64 encoded length caps (`413 PAYLOAD_TOO_LARGE`); enforced strict `^(portfolio|services|team|general)\/[a-zA-Z0-9._-]+$` key validation (including invalid `replaceKey` -> `400 INVALID_ASSET_KEY`); enforced `nosniff`, strict `CSP`, and `Cross-Origin-Resource-Policy: cross-origin` on R2 asset responses. | `security_remediation.test.js` #5, `contract_and_security.test.js` #2 |
| **Weak Password Floor & Incomplete JWT Claims** | Medium | Raised `validateStrongPassword` and `isValidBootstrapPassword` minimums from `8`/`10` to `12` chars unconditionally + expanded weak denylist (`COMMON_WEAK_PASSWORDS`); enforced `header.typ === 'JWT'`, valid `iat`, and `nbf` validation in `verifyJwt`. | `security_remediation.test.js` #5 |
| **Hidden Team/Testimonials Exposure & Unsafe URL Schemes** | Medium | Filtered `visible === false` team members and `isApproved === false` testimonials from public `GET /team`, `GET /testimonials`, and `GET /bootstrap` unless authenticated admin requests `?includeInactive=true` / `?all=true`; enforced `isSafeUrl` across services, portfolio, and team links. | `security_remediation.test.js` #4 |
| **API Security Headers & Repository Hygiene** | Medium | Enforced `X-Frame-Options: DENY`, `Cross-Origin-Opener-Policy: same-origin`, `Cross-Origin-Resource-Policy: same-site`, `Cache-Control: no-store`, strict API `CSP`, and production HSTS; deleted `/backend/.wrangler/cache/wrangler-account.json` and ignored `.wrangler/`, `data/`, and `.dev.vars*`. | `security_remediation.test.js` #5 |

## 2. Core Cryptographic & Access Controls (`backend/src/**`)

- **Password Hashing:** WebCrypto `PBKDF2-HMAC-SHA512` (`100,000` iterations, 16-byte random salt, `$pbkdf2-sha512$v=1$i=100000$...`), constant-time verification (`timingSafeEqualStrings`), transparent `$argon2id$` legacy migration.
- **Role-Based Access Control (RBAC):** `super_admin` > `admin` > `editor`, completely isolated from `client` (`accountType` separation + live `token_version` verification).
- **SQL & Input Safety:** 100% parameterized D1 prepared statements, `sanitizeText` XSS stripping, explicit field whitelists, and recursive secret/prototype stripping in `updateSiteSettings`.
